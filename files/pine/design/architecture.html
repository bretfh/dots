hecl — architecture overview

One-line read: a programmable editor built as a network of sento actors, with a CLOS class hierarchy of modes driving behavior, and a uniform tell / ask verb set for anything addressable.

Runtime topology

Four kinds of things, all addressable through the same actor system:

User

Keyboard, mouse, QML callbacks.

External input source, not an actor itself.

Client

Actor with a dispatch loop. Owns frame, windows, focused window, pending-keys, mode stack, kill-ring, completion state, renderer, buffer-modes cache.

Window manager for the buffers it hosts.

src/client.lisp

Buffer

Actor owning an immutable buffer-state, undo ring, subscriber list, last highlights.

Doesn't know who renders it.

src/buffer.lisp

Other actors

Tree-sitter parser, buffer registry, event bus, agent registry, LSP / LLM adapters (future).

From inside hecl they're just named mailboxes.

Server / client relationship (tmux model)

The server holds the runtime; clients are actors inside it.

Multiple clients can attach to one server. Buffers are shared across clients; windows and scroll positions are per-client. Kill the last client, server keeps running.

Files and load order

From hecl.asd:

package → server → actor → event → hooks → face → buffer → window → client → layout → mode → #+lqml bridge → ts → render → file → shell → term → keymap → kill-ring → complete → prompt → editor → user → main

Early files are infrastructure (actors, state classes, faces). Middle files define the buffer/layout/mode substrate. Late files are commands, rendering, the LQML bridge, and user-facing entry points.

Buffer model

Every buffer is a text buffer at the data layer.

  • buffer-state: immutable — lines (fset:seq), marks (fset:map), meta (fset:map), tick (edit counter). src/buffer.lisp:4–8
  • snapshot: frozen view for rendering — name, tick, lines, line-count, point-line, point-col, highlights, meta. src/buffer.lisp:10–18
  • Per-buffer actor stores (state undo-ring subscribers hl-cache).
  • Edits: message comes in → dispatch to mode → mode produces a new state → setf sento.actor:*state* → notify subscribers.
  • Subscribers are client renderer actor refs; eq-identity for add/remove.
  • buffer-local state/snap :key &optional default reads meta. src/buffer.lisp:38–47

Mode system

Modes are CLOS classes. dispatch-message is a generic function dispatched on mode; call-next-method walks parents.

Class hierarchy

base-mode (queries, subscribe, undo, set-local, highlights) ├── text-mode (edit verbs: insert / newline / backspace / ...) │ ├── lisp-mode (ts-language :commonlisp) │ └── repl-mode (overrides :newline → repl-submit) └── terminal-mode (writes → PTY; reads synthesized from gterm)

src/mode.lisp:6–15 (base-mode); 175–245 (text-mode); 249–257 (lisp/repl); 275–312 (terminal)

Dispatch-message protocol

Buffer actor's receive reduces to:

(lambda (msg)
  (let* ((state (first sento.actor:*state*))
         (mode (or (find-mode (buffer-local state :mode :base-mode))
                   (find-mode :base-mode))))
    (dispatch-message mode sento.actor:*self*
                      (first msg) (rest msg))))

src/buffer.lisp:226–236

Methods handle their own state updates and replies by touching sento.actor:*state* directly and calling sento.actor:reply. Unknown tags fall through call-next-method.

Per-mode fallback

When no keymap entry matches a key, the mode's fallback slot runs:

  • text-mode: insert the char if it's printable and unmodified.
  • terminal-mode: encode Ctrl-letter → control char, or special keys via key-bytes, then tell buf :insert :text — the terminal-mode dispatch-message method forwards to the PTY.
  • base-mode: no fallback (bound keys only).

src/mode.lisp:316–347

Layout system

Buffers that display structured content (dired, compile, grep, completing-read) render a virtual node tree into their text. The hecl.layout package owns this.

Containers: vstack, hstack, box, grid, list-node.

Content: text-node, separator, field.

Interactive: selectable, action.

Container: layout holds root node, target buffer name, state (plist), width.

Registered per-buffer on the server ((hecl.server:layouts srv)).

render-layout produces lines; marks anchor each node's start/end for interactive hit-testing.

src/layout.lisp

This is the substrate modes like dired-mode will use: keep :insert etc. as no-ops, override :activate (RET) to find the selectable at point via buffer-layout and fire its callback.

Key dispatch

QML forwards keys to hecl:on-key. dispatch-key walks:

  1. pending-keys — active chord prefix (e.g. C-x …).
  2. Current mode's keymap chain (mode → parent → ... → base-mode).
  3. global-keymap — truly global (chord prefixes, M-x, C-x C-e).
  4. Mode's fallback (insert-char for text, PTY-forward for terminal).

src/keymap.lisp:75–133

Bindings split

WhereWhat lives there
global-keymap C-x chord prefixes (C-x C-f, C-x C-s, C-x b, C-x n, C-x r, C-x C-e), M-x. Shared across all modes.
text-mode keymap Arrows, Emacs-style movement (C-f/b/a/e/n/p/d, M-</>), editing (backspace, newline, delete-char), kill/yank (C-w, M-w, C-y, M-y), C-SPC mark, scroll, undo.
terminal-mode keymap Empty. Inherits C-x and M-x from global; everything else falls to the fallback and goes to the PTY.

Rendering pipeline

Two threads, loosely coupled via an fset:map render-state.

Actor path (dispatcher thread)

Renderer receives :snapshot, :resize, :switch-buffer, :force-render. Updates windows and marks :dirty in render-state.

On :snapshot, if the buffer's mode declares a ts-language and the snapshot's tick is newer than the last parsed tick, send :parse to ts-actor.

src/render.lisp:72–124

Paint path (Qt thread)

60 Hz persistent tick via qsingle-shot 16. If :dirty, render focused window to the frame-cells buffer, push to QML Canvas. Re-arms itself inside unwind-protect so errors in the body never wedge the loop.

src/render.lisp:293–333

Invariant: paints run independently of parsing. If tree-sitter is busy, slow, or unloaded, typing still shows up.

Terminal integration

Terminals aren't a side channel. They're a mode.

  • Open a terminal → buffer actor + gterm (libghostty-vt) + forkpty pair + reader thread.
  • Buffer gets mode :terminal-mode. State is vestigial; real "text" lives in gterm's cell grid.
  • Writes: (tell terminal-buf :insert :text "ls\n") → terminal-mode's dispatch-message → term-write → write(master_fd, ...).
  • Reads: (ask terminal-buf :text) → terminal-mode's :get-text override → gterm-text decodes the grid into a multi-line string.
  • :get-snapshot / :get-state: synthesize a state from gterm-text plus the real cursor position via gterm-cursor-row-of / gterm-cursor-col-of.
  • Subscribers and :highlights on terminal-mode fall through to base-mode — harmless.

src/term.lisp · src/mode.lisp:275–312

This is why tell is the single verb: same message, different semantics per mode, via CLOS. No terminal-send-key in the public API anymore — that path collapsed into the mode method.

Interactive API — buffer / ask / tell

Three primitives in hecl.buffer, re-exported into scratch's default package hecl-user:

(buffer X)                       ; coerce: string/actor/:current/:focused/nil
(ask TARGET QUERY &rest ARGS)    ; :server / :client / buffer queries
(tell TARGET TAG &rest PLIST)    ; any tag the target's dispatch handles

Verb tables: src/buffer.lisp:+server-verbs+ / +client-verbs+ / +buffer-verbs+

Every target supports (ask TARGET :describe) returning its verb list.

Full reference: design/api.org.

Bootstrap sequence

hecl:main wires everything up:

  1. start-server → actor-system + commands + global-keymap + faces + modes + buffer-table.
  2. ts-runtime created (libs not loaded yet).
  3. Event bus + agent registry + local agent actors spawned.
  4. start-client server → client instance + pushed onto server's clients list.
  5. setf hecl.client:*client* = that client, making it the ambient context.
  6. install-default-faces.
  7. start-editor → buffer-registry actor, ensure-ts loads libtree-sitter, renderer actor + ts-actor spawned, default commands + bindings + modes installed, scratch buffer + window created, subscribed to buffer, scratch's :package set to :hecl-user.
  8. run-init-hooks.
  9. (#+lqml init-ui client) schedules lispReady = true 100 ms later; QML then reports real size and the render loop kicks off on the first :resize.

Status

Shipped (Order 0)

  • Client / server split; globals → slots.
  • Ambient *client* only; no other dynamic specials for per-session state.
  • Actor messages: (:tag :k v …) plists everywhere.
  • Buffer-local vars via typed accessor on meta.
  • Render-loop unwedge fix (persistent tick + unwind-protect).
  • Parse-loop CPU fix (per-buffer last-parsed-tick gate).
  • Subscribe / unsubscribe by identity.
  • Deferred render-loop start on first resize.

Shipped (Order 1)

  • Mode system: CLOS classes, defmode, dispatch-message generic.
  • base-mode, text-mode, lisp-mode, repl-mode, terminal-mode.
  • Terminal integrated via the mode; no side-channel API.
  • Tree-sitter refactored to hold a language map.
  • find-file picks mode by file extension.
